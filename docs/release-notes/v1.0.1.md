# Audial Synth 1.0.1

Two changes, both about what the plugin tells you and tells the API. The synth engine, the
Resynth flow and the presets are unchanged from 1.0.0.

- **The machine warm-up is explained.** When Audial has to start a worker for your job, the
  Resynth panel now says so instead of counting seconds against an estimate that never
  included the start-up: "Warming up the machine — the first request takes a few minutes
  longer than usual; every run after this is faster", then "Working on your job". A warm job
  looks exactly as it did before. The panel also asks the API whether the service is warm as
  soon as it opens, and shows a small Ready / Warming up dot next to Browse, so a slow first
  run is no longer a surprise.
- **The plugin identifies itself to the API** (`x-audial-client: audial-synth/1.0.1` and a
  matching `User-Agent`), so renders made from the synth are attributed to it rather than
  landing in an unlabelled bucket. Nothing new is sent: no sample, no preset, no identifier
  beyond the name and version of the plugin.

Both are backwards compatible with an API that does not serve them yet: no warm-up object on
the execution means the old status line, and a missing `/api/functions/status` route (404)
means no dot.

## Install

1. Download `AudialSynth-macOS.zip` (macOS) or `AudialSynth-Windows.zip` (Windows) below and
   unzip it.
2. macOS: move `AudialSynth.vst3` to `~/Library/Audio/Plug-Ins/VST3` and `AudialSynth.component`
   to `~/Library/Audio/Plug-Ins/Components`, or run `AudialSynth.app` directly. This build is
   signed with a Developer ID and notarized, so Gatekeeper lets it open without a detour.
3. Windows: copy the whole `AudialSynth.vst3` folder into
   `C:\Program Files\Common Files\VST3` and rescan plug-ins; `AudialSynth.exe` runs from
   anywhere. The Windows build is not code-signed yet, so SmartScreen asks once: More info →
   Run anyway.
